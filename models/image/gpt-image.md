## モデルと使い分け

| モデル | 推奨用途 |
|---|---|
| `gpt-image-2` | **新規は基本これ。** 最高品質の生成と編集、文字の多い画、写実、合成、同一性を要する編集 |
| `gpt-image-2` の `quality="low"` | 速度と単価が支配的なとき。**多くの用途で十分な品質** |
| `gpt-image-1.5` / `gpt-image-1` | 既存ワークフローの互換維持のみ |
| `gpt-image-1-mini` | 大量の下書き・試作 |

**`quality="low"` から始めて評価する**のが公式の推奨。小さい文字・密な情報パネル・
接写の顔・同一性を要する編集・高解像度のときだけ `medium` / `high` と比較する。

## サイズの制約

`size` に任意の解像度を渡せるが、全部満たす必要がある。

- 最大辺 **3840px 未満**
- 両辺が **16の倍数**
- 長辺:短辺が **3:1 以下**
- 総画素 **655,360 以上 8,294,400 以下**

**2560×1440（2K）を超えると結果が不安定**になるので実験的な扱い。

よく使う値：1024×1536（縦）／1536×1024（横）／1024×1024／2560×1440。

## プロンプトの構造

```
背景・場面 → 被写体 → 主要な細部 → 制約
```

**用途を書く。** 広告なのか、UIのモックなのか、インフォグラフィックなのかを書くと、
モードと仕上げの水準が決まる。

長くなるなら**短いラベル付きの区切りか改行**を使う。1つの長い段落にしない。

**形式は自由。** 最小限のプロンプト、説明的な段落、JSON風、命令形、タグ形式のどれでも
意図と制約が明確なら機能する。**本番の仕組みでは、凝った構文より読み流せる型を優先する。**

### 写実にするとき

**`photorealistic` という語を直接入れる。** 「real photograph」「taken on a real camera」
「professional photography」「iPhone photo」も効く。

**カメラの仕様は緩く解釈される。** 物理シミュレーションではなく、見え方と構図の
指定として使う。

質感の指定は具体的に。毛穴、しわ、布の擦れ、あり得る不完全さ。
**スタジオ的な磨き上げを示唆する語を避ける。**

### 人物

規模・身体のフレーミング・視線・物との相互作用を書く。
「全身が見えていて足まで入る」「テーブルに対して子供の大きさ」
「カメラではなく開いた本を見下ろしている」「両手が自然にハンドルを握っている」。

## 編集の定型

**これが最重要。**

```
「Xだけ変える」＋「それ以外は全部そのまま」
```

**反復のたびに保持リストを繰り返す。** 繰り返さないとドリフトする。

外科的に直すなら、**彩度・コントラスト・レイアウト・矢印・ラベル・カメラ角度・
周囲の物を変えるな**と名指しで書く（→ principles/image-repair.md）。

## 透明背景（preview）

`background="transparent"` ＋ `output_format="png"` または `"webp"`。**jpeg は不可。**

- 被写体を完全な透明背景に孤立させると明示する。**風景・単色の背景・市松模様・
  不要な影を除外する**と書く
- **編集のたびに「透明背景を保持」と書く。** 書かないと背景が戻る
- PNG では `output_compression` を省く
- 返ってきた画像のアルファチャンネルを、後段の処理で壊さない

**物アセットの切り抜きに直接使える**（→ templates/asset-card.md）。

## 文字

**引用符か ALL CAPS で literal に書く。** 書体・サイズ・色・配置を制約として指定する。

**ブランド名や珍しい綴りは1文字ずつ綴る。**

小さい文字・密な情報パネル・複数書体のレイアウトは `medium` / `high` を使う。

## 複数画像の参照

**番号と説明で参照する。** 「Image 1: 商品写真… Image 2: スタイル参照…」。
そして**どう相互作用するか**を書く。「Image 2 のスタイルを Image 1 に適用する」。

合成するときは**どの要素がどこへ行くか**を明示する。

## 長いプロンプトより小さな反復

長いプロンプトも機能するが、**きれいなベースから始めて、小さな単一変更で詰めるほうが
デバッグしやすい。** 「照明を暖かく」「余分な木を消す」「元の背景に戻す」。

「さっきと同じスタイル」のような参照で文脈を使えるが、**ドリフトし始めたら
重要な細部を書き直す。**

## キャラクターの一貫性

公式が2段階のワークフローを載せている。

1. **キャラクターのアンカーを作る。** 外見・比率・衣装・トーンを固定した1枚。
   無地に近い背景でキャラだけを見せる
2. **その画像を編集入力にして続きを作る。** 「同じ服／同じ顔立ちと比率と配色／
   同じ性格。**キャラを再設計するな**」

**既存のキャラクターシート運用と同じ構造**（→ templates/character-sheet.md）。
