## モデル名だけでは実務を表せない

**バージョンで使える機能が変わる。** `platforms/higgsfield.md` の「ホストによって違う」と
同じ問題が、同一ブランドのバージョン間で起きる。

| バージョン | 状態（2026-08-28） |
|---|---|
| V8.2 | **既定。** 2026-07-24 から |
| V8.1 | 選択可能。2026-06-10〜07-23 が既定だった |
| V8.0 Alpha | 廃止 |
| V7 | 選択可能。**一部の機能はここでしか動かない** |
| Niji 7 | アニメ系。2026-01-09 |

**指定するときは `host × model × version` で持つ。** 「Midjourney で作った」だけでは
再現できない。

## V8 は指示どおりに実行する

**V7 はプロンプトを提案として扱い、既定の美学を強くかけていた。V8 系は文字どおり実行する。**

したがって**ムードの語を仕様に置き換える。**

- 「劇的な照明」ではなく「頭上からのキーライト1灯、フィルなし」
- `--raw` で、残っているハウススタイルの適用量を制御する

**既存の「形容詞を積まない。動きとレンズで書く」と同じ方向**
（→ principles/shot-structure.md）。

## 制御がプロンプトの外にある

**V8 では創作の制御が Personalization プロファイルへ移った。**
学習済みプロファイルと `--stylize 1000` の組み合わせが最良とされる。

**これは再現性の観点で厄介。**

- プロファイルはアカウントに紐づく。**チームで共有できない**
- 蓄積したポイントで挙動が変わる。**時間とともに変化する**
- 案件をまたいで同じプロファイルが効き続ける

`principles/prompt-compilation.md` の「B. プロンプト外で固定される」の中でも、
**特に外部化の度合いが強い例。**

## Omni Reference の注意

キャラクターの同一性に使う `--oref` は、**V8 のジョブでも受け付けられるが、
公式の互換表に「(Uses V7)」と注記されている。つまり V7 がレンダリングする。**

**同一性を求めると V8 の画質特性が得られない可能性がある。** ここは要検証。

## 契約前に確認すること

**著作権訴訟が継続している。** 学習データをめぐって作家・スタジオから訴訟が続いており、
**商用利用の法的問題は未解決**と複数の資料が書いている。

出版社の案件で使う場合、`OPERATIONS.md`「クライアント原稿・第三者著作物の入力」の
4段階判断を通す。**プラットフォームの規約より、クライアント契約側の制限が上位。**
