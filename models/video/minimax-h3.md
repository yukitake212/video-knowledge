## モードを最初に決める

**モードが決まる前にプロンプトの形は決まらない（Tier A）。** 公式Skillの工程1が
モード判定になっている。

| モード | 何をするか |
|---|---|
| T2VA | テキストだけから音つき映像の時間軸を組み立てる |
| I2VA | 第1フレームから前へ展開する |
| FL2VA | 第1フレームと最終フレームの間の連続した経路を書く |
| L2VA | 最終フレームへ収束するように、もっともらしい冒頭を推定する |
| Ref2VA | 参照を使う。**文法が別**（下記） |

## Base系（T2VA / I2VA / FL2VA / L2VA）の出力フィールド

**この順序で書く（Tier A）。**

```
integrated_multimodal_description
overall_soundscape
non_diegetic_music
```

- 各ショットは**構図・被写体・環境・動作・カメラ・音・参照内容が現れる正確な位置**で
  記述する（Tier A）
- **筋書きの要約を書かない。** 未解決の参照ラベルを残さない。要求した尺と合わない
  時間指定をしない（Tier A）
- 記述の合計尺を要求した尺に合わせる。**4〜15秒**（Tier A）
- 「cinematic」「beautiful」のような抽象語より、具体的な視覚・音の細部を優先する（Tier A）
- キーフレームを使うモードでは、**第1・最終フレームが時間軸のどこに接続するかを
  明示する**（Tier A）

## Ref2VA の文法は別

**この順序（Tier A）。**

```
subject_definitions
summary
retention_analysis
detailed_description
overall_soundscape
non_diegetic_music
```

`retention_analysis` が特徴的で、**参照から何を保持するかを明示する節**が
独立して存在する。既存の「参照ごとに使う情報と使わない情報を書く」を、
公式が節として持っている形（→ principles/shot-structure.md）。

**保証ではなく宣言。** この節は「各参照がどこで**全面保持・部分保持・転用・再利用**される
べきか」を記述するもので、**`fully_preserved` と書けば実測上完全に保たれる、という
評価値ではない。** 公式文書に保持率の定量値は無い
（2026-08-31 / 外部情報。MiniMax公式のFull-Reference Format Guide と ref-en.txt を一次で確認。
**H3 Ref2VA のみ。Seedance や Wan へ同じ欄名を一般化しない**）。

**ラベルの使い分けも公式に定義がある。** `<Subject>` は複数ショットで再利用する可視内容、
`<Picture>` は**具体的なフレーム・キーフレーム・構図アンカー**、`<Video>` は編集元・継続・
時間構造、`<Audio>` は音声信号。**同じ画像でも `<Subject>` として抽象化するか
`<Picture>` として具体的な構図に使うかで役割が変わる。**

参照ラベルは `<Picture 1>` `<Video 1>` `<Audio 1>` の形式で、
**全節を通して一貫させる（Tier A）。**

## 書く言語

**書き直した各節は英語で書く。ただし台詞・歌詞・画面に映る文字は元の言語のまま
保持する（Tier A）。**

日本語の台詞を扱う案件ではここが効く。地の文は英語、台詞は日本語のまま。

### 話し方の指定をどこに書くか

**地の文（英語）に一文足すと、台詞の速さと調子を指定できる。台詞は日本語のまま
引用符で囲む。** `principles/sound.md` の「全体の音の契約はスタイル前置き、その瞬間の
キューは各ビートの記述内」に沿って、**台詞の直後に置く**。

**全部を同じ調子にすると平板になる**ので、カットごとに調子を変える
（2026-08-28 / 自社検証。1本の完成尺で全カットに適用。1案件1回）。

## 参照の役割分類

公式マニュアルが12種類を定義している（2026-08 / 二次紹介）。
**既存の5種類より細かいので、こちらを採る**（→ templates/shot-ir.md）。

character（顔・体を固定）／object（商品・小道具）／scene（場所）／
keyframe（フレーム。第1か最終かを明示）／voice（声質）／storyboard（絵コンテに従う）／
style（見た目）／composition（構図と配置）／audio reuse（音源をそのまま使う）／
motion（動画から動作を取る）／camera（カメラの動きを取る）／video edit（編集対象）

**ファイルは番号を付けて役割を宣言する。** 役割を書かない参照は無視されやすい、と
公式マニュアルが述べている。

## 仕様

以下は二次資料。**自社未確認。**

- 4〜15秒、最大2K、24fps、ネイティブのステレオ音声
- 参照は9画像＋3動画＋3音声（合計12ファイル）
- テキストのみのモードはプロンプト最大7,000文字
- 音楽を止めるには `non_diegetic_music: N/A` と明示する
- カメラの動きは「truck left + pan right」のように具体的に書く。
  「orbit the scene」のような曖昧な要求は弱い
- **H3 はデフォルトでカット割りする。** ワンテイクが欲しいなら明示する

## 公式が挙げる6つの失敗

二次資料。**自社未検証。**

| 失敗 | 対処 |
|---|---|
| 全体を1段落で書く | 3ブロックに分ける |
| ファイルをアップしたが役割を書いていない | 全ファイルに役割を書く |
| 音楽を要求しつつBGMを禁止する | どちらか消す。または場面ごとに分ける |
| ワンテイクが欲しいのに Shot 1 / Shot 2 と書く | 連続した1段落にする。ショット構造を書かない |
| 参照画像なしで顔の一貫性を求める | 顔固定として役割を書いた画像を渡す |
| ファイル無しでプロンプトが短すぎる | 被写体の外見＋場面＋動作＋様式を最低限書く |

3つ目と4つ目は自社の既存則と一致する。矛盾する指示を混ぜない、編集文法を宣言する
（→ principles/shot-structure.md、principles/guards.md）。

## 2D・アニメ調について

ある第三者ホストが、**H3 は線の質とキャラクタープロポーションを保持する、多くの動画モデルが
苦手とする部分だ**と述べている（2026-08 / ホストのブログ。**自社未検証、一次資料でも確認できず**）。

事実なら漫画原稿・アニメ調の案件で候補になる（→ principles/still-to-motion.md）。
**確かめる価値がある。**

## H3 Max

**H3 standard と同じ扱いにしない。** 別の変換が要る（2026-08 / 二次紹介）。

fal 経由の H3 Max は**プロンプト拡張のモード**を持ち、こちらが書いたものが
書き換えられてからモデルへ渡る。拡張後のプロンプトを取得できる場合がある。

**こちらのプロンプトと拡張後の差分は知見になる**（カメラ用語、音の構造、環境描写の
足され方）。ただし**拡張後のプロンプトを public リポジトリへ保存してよいかは
利用条件と著作権を別途確認すること。** 未確認。
