# 一度書いて、以後そのまま貼るブロック

**このファイルにあるのは「読んで判断するもの」ではなく「貼るもの」。**

## なぜ分けるか

**知識には2種類ある。**

| | 使うときに何をするか | 飛ばせるか |
|---|---|---|
| **読んで判断する** | 読んで、理解して、このカットに当てはめる | **飛ばせる。適用が毎回の判断だから** |
| **そのまま貼る** | 貼る | **飛ばすと出力が不完全になる** |

`principles/` はほぼ全部が前者。**そして実案件で一発で通ったものは、ほぼ全部が後者だった**
（→ `OPERATIONS.md`「自社1案件目の実測」）。

| 一発で通った | 形 |
|---|---|
| 物アセット（寸法をmmで） | **数値。判断が要らない** |
| テロップカード2枚 | 定型 |
| 書影エンドカード | 空白の禁止列挙という型 |
| 空白を作らせる3箇所 | 同上 |

**反復したものは全部、判断が要るものだった。**

## 共通の規律

**① 一度決めたら、同義語も変えない。** ブロックは案件ヘッダに置き、**一字一句そのまま**
各生成へ貼る。「前のショットと同じ」はモデルに通じない。**毎回全文を書く。**

**② 新しい状態は新しいブロック。上書きしない。** 同じ人物の別の状態、同じ場所の別の面は
**別のブロックとして持つ**（→ 下「命名」）。

**③ 版で管理する。** 作り直したら版を上げ、**そのショットでは有効な版だけを参照する。**
古い版が残っていると、どれが正本か分からなくなる。

**④ 書けるようになってから作る。** ここに型を足すのは、**1案件で手書きして実際に効いた**
ものだけ。**未検証の様式を置くと、使われたときに検証済みに見える**（→ `../CLAUDE.md`）。

## 命名

**1要素1名前。** 同じものが3つの名前で呼ばれ始めたら、どれが正本か誰も分からなくなる。

```
@char_[案件]_[名前]        人物
@char_[案件]_[名前][状態]  同じ人物の別状態 ← 別アセット。上書きしない
@loc_[案件]_[名前]         場所
@loc_[案件]_[名前]_[面]    同じ場所の別の面 ← 別アセット
@prop_[案件]_[名前]        物
```

**確定した空間マスターは再生成しない。** 同一プロンプトでも同じ空間は出ない
（→ `../platforms/model-quirks.md`）。**別アングルが要るなら、画像で渡せる経路を選ぶ。**

## 型1 — ハウススタイル

**実写調は `house-style-live-action.md`。** 10節の骨格をそのまま貼る。
**素材が漫画原稿・挿絵なら貼らない。**

**アニメ調のブロックはまだ無い。** 12軸から書く（→ `../principles/visual-style.md`）。

**このファイルの原型がこれ。** 「毎回そのまま貼る固定文」「一字一句そのまま使い回す」
「移植できる資産は中身ではなく骨格のほう」——**他の型も同じ性質を目指す。**

## 型2 — 声のロック

**声は生成のたびに振れる。一度書いて固定する。**

```
[話者名] — voice:
  音域と質      [低い／高い／かすれ／芯の太さ]
  話す速さ      [数値があるならUI側。ここには質だけ]
  抑揚の幅      [平坦／広い／抑えている]
  話し方の癖    [短く切る／間を置く／語尾を落とす]
  出してはいけないもの [演劇的な色／語尾上がり／過剰な感情]
  言語・訛り
```

**規律。**

- **UIで持てる値をブロックへ書かない。** 速さ・ムード・強度がUIにあるなら、そこへ持たせる。
  **両方に書くと指示が二重になって競合する**（→ `../principles/sound.md`）
- **演技は感情ラベルではなく発話行為で書く。** 「悲しそうに」ではなく「宣言ではなく懺悔」。
  **相手・目的・こらえているもの・推移**を分ける
- **数週間離れたショットで同じ声が要るなら、生成で揃えようとしない。**
  画を先に作り、**音声だけを別パスで差し替える**

（2026-08-31 / 自社検証。発話行為で書いた1本は一発で通り、感情ラベル寄りの2本は不採用）

## 型3 — 参照のコネクタ

**参照は「渡す」だけでは効かない。何を取り、何を取らないかを書く。**

```
@[タグ] — [役割を1語で：identity / look / composition / motion / …]
  使う情報    [この参照から取るもの]
  使わない情報 [取らないもの。とくに背景・照明・フレーミング・画風]
  いつ効くか   [全編／このビートだけ]
```

**規律。**

- **参照が既に持っている情報を、プロンプトで書き直さない。**
  書き直すと**モデルが参照より文章を優先する**（顔・髪型・肉付きが動く）
- **役割は12種類から選ぶ**（→ `../principles/shot-structure.md`）
- **写真参照を先、図式や補助を最後に添付する。** 添付の順序が画風の votes を決める
  （2026-09 / 外部情報。**自社未検証**）
- **参照が3枚以上になったら統合条項を書く**（貼り付け感・照明の不一致・切り抜きの縁）

## 型4 — 空白を作らせる

**「空けろ」だけでは空かない。置かせたくないものを名指しで列挙する。**

```
[領域]は完全に空にする。[肯定形で、そこに何があるべきか：無地の背景と、
そこへ落ちる柔らかい影だけ]。
[置かせたくないものを列挙：想定される描き足しを全部]。
```

**列挙の実例**（→ `../principles/typography.md`。**3箇所とも一発で通った**）。

| 用途 | 禁止したもの |
|---|---|
| 肖像の座を空ける | 肖像・写真・額縁・顔・イーゼル |
| 文字の1列を空ける | ダッシュ・点・線・枠・箱・影・輪郭 |
| 実物を置く場所を空ける | 本・装画・イラスト・写真・プレースホルダ・枠・罫 |

**失敗したら、出てしまったものを列挙へ足す。** 予防で全部を並べない。

## 型5 — 禁止（FORBIDDEN）

**案件ごとに1回作って、毎回貼る。** カットごとに書き直さない。

**書き方は `../principles/guards.md`。** ここに置くのは運用だけ。

- **否定は末尾に一括。** 記述の途中に挟むと画の描写が途切れる
- **単独で立つ否定を作らない。** 肯定側が書けていないということ
- **語を出すこと自体が召喚になる。** 「旗を出すな」で旗が戻った実例がある。
  **無地の布と書くほうが消える**（2026-09 / 外部情報。**自社未検証**）
- **塞いだぶんの受け皿を用意する。** 動くものを1つに限定すると、そこへ要求が集中して暴走する
