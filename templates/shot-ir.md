# ショット仕様の型

**モデルを決める前に埋める。** 埋め終わってからモデルを決め、そのモデル向けの
プロンプトへ変換する（→ principles/prompt-compilation.md）。

モデルを変えるときは、前のプロンプトを手直しせずにここへ戻る。

**「狙い」の3欄とスタイルの5欄は役割が違う。** 狙いは**このカットの物語機能へ
全体規則を適用する欄**、スタイルは**全体規則のどれを参照し、どこだけ外すかの欄**。
**全体仕様をここへ複製しない**（→ `principles/visual-style.md`「三段階で持つ」）。

**「繋ぎ」の6欄は、生成の前に埋める。** 編集で余ったフレームを探すのではなく、
**繋ぐための素材を生成段階で作る**（→ `principles/trailer-structure.md`「繋ぎ目は設計する」。
2026-09 / 外部情報。**自社未検証**）。

## 使い方

**参照の役割は12種類から選ぶ。** 既存の5種類（identity / set / light motivation /
interaction object / look）は不足していた。keyframe・storyboard・composition・motion・
camera・voice・audio reuse・object が足りない（→ principles/shot-structure.md）。

**「いつ効くか」を書く。** 全編を通して効く参照と、特定のビートでだけ効く参照がある。
書かないと、モデルが全編に適用してしまう。

**優先度を先に決める。** 予算が足りないときに何を落とすかは、書き始めてからでは決められない
（→ principles/prompt-compilation.md）。

**「UI・APIで固定する値」を分けて持つ。** 尺・アスペクト比・解像度をプロンプト本文に
書くと、モデルが無視すべきノイズになる。ByteDance の実践ガイドは
「生成パラメータはプロンプトに書かない」と明記している
（2026-08 / 二次紹介。原典は未確認）。

**アスペクト比は、モードによっては「固定する値」ではない。** H3 では画像を
first frame として渡すと**出力比率が入力画像から決まり、選べない**。
参照として渡す場合は別に指定できる（2026-08-31 / 一次で確認。
→ `models/video/minimax-h3.md`「画像入力の要件」）。
**アセットを作る前にどちらで渡すか決める。**

**空欄を埋めようとしない。** 該当が無ければ空でよい。特に「状態の素材」「音楽」
「ホスト側の書き換え」は、無いことが情報になる。

## 案件ヘッダとの関係

被写体と参照の実体は案件ヘッダの ASSETS 台帳にある
（→ templates/shot-schema.md）。ここではIDで参照するだけにして、
実体を二重に書かない。
