# Magnific（旧Freepik）

**現行の制作プラットフォーム（2026年8月〜）。**
以下は 2026-08 に公式ドキュメント・製品ページで確認。**仕様は変わる。都度確認すること。**

## 基盤とモデル

- 単一モデルではなくマルチモデル基盤。Veo / Kling / Seedance / Wan / PixVerse / Runway / Hailuo / Sora / LTX を用途別に選ぶ。単一モデル障害への保険にもなる
- 尺はモデル依存でおおむね4〜15秒。Seedance 2.5は4〜30秒のネイティブ生成を謳う
- マルチショットは1生成で最大6ショット、各ショットに個別のプロンプトと尺を設定できる。対応はWan 2.5/2.6・Kling 3.0系・Seedance 1.5 Pro/2.0。Kling 3は合計15秒以内・各ショット3秒以上
- マルチショットは速いがトランジションをAIが決めるので制御が弱い。**精密な繋ぎや複数モデルの混在が要る本番はカット別生成＋Video Editorで合成**、が公式の使い分け

## Spaces とワークフロー

- **Spaces** — 画像・動画・音声のノードを接続する視覚的なワークフロー。
  Video Generator は40以上の動画モデル、開始／終了フレーム、複数参照、
  動画参照、音声入力を扱える（2026-08-28確認 / 公式Docs）
- **生成から仕上げまで同じ基盤に置ける。** 有料プランは画像・動画・音声モデル、
  Spaces、画像／動画編集、Magnific のアップスケーラを同一環境に持つ。
  Premium+ / Pro では Topaz のアップスケーラも含む
- **Metadata Export / Lineage**（Pro / Enterprise）— プロンプト、モデル、参照、修飾子、
  生成者、日時を CSV / PDF へ出力でき、元のアップロードから編集・生成までの系譜を追える。
  **クライアント案件の入力経路の記録に使える**
  （→ OPERATIONS.md「クライアント原稿・第三者著作物の入力」）。
  対象外のプランでは作業文書へ手で記録する

**実案件で Spaces を使った実績はまだない。** ノードを組む時間と、
カット別生成＋Video Editor で合成する時間のどちらが速いかは測っていない。

## 参照とキャラの一貫性

- 参照の渡し方：スタート画像のみ／スタート＋エンド画像（間の変化を生成）／PixVerse 5.5などは画像に直接描き込む Visual Prompt
- エンド画像指定はカットの着地点を固定できる。表情が変わりきる系のカットに効く
- キャラの一貫性はImage GeneratorでCustom Characterを学習させ、その画像をスタートフレームに使う。Custom Styleも同じ流れで画づくりを揃えられる
- HiggsfieldのCinema Studio・Cast・Soul ID・Lipsync StudioはHiggsfieldの機能でMagnificには無い。Magnific側の対応物はCustom CharacterとSpeak / Lip Sync

## 音声とリップシンク

- リップシンクは専用ツールが2つ：**Speak**（画像・動画から喋るクリップを新規生成、30以上の言語、最長5分）と、**Clip Editor内のLip Sync**（既存クリップの口を音声に合わせる）。動画モデル本体にリップシンクさせる必要はない
- 音声はVoice GeneratorがありElevenLabs v3を選べる。ボイスクローンは音声サンプル1〜5本から作成でき、2話者の掛け合いも1回で生成できる
- 音声生成のコツ（公式）：句読点で間を作る、全角大文字や変わった書式は避ける、読み間違いは表音表記で書き直す。クローン用サンプルは無音・無音楽で合計30秒以上、棒読みにしない

## 契約・データ面

2026-08 に公式のプライバシーポリシー（April 2026 版）と Docs で確認。
**以下はポリシー本文の読み取りであって、法的な助言ではない。条件は変わる。都度確認すること。**

### 通常プラン（Individual / Teams / Business）

- **アップロードした画像・音声は、Magnific および第三者モデル提供者のモデルの
  学習・改善に使わない**とポリシーに明記されている
- **ただし「第三者に送られない」という意味ではない。** Magnific は入力と出力の
  収集・保存・ホスティング・送信を行い、**選んだ第三者モデル提供者が再委託先として処理する**。
  学習に使わないことと、外部事業者が一切処理しないことは別条件
- **画像・音声を除く入力と出力は、扱いが違う。** セキュリティとコンプライアンスに加え、
  入力・出力・フィードバックの関係を研究してサービス改善に使う場合がある、と記載されている。
  **つまり原稿画像とプロンプト文章は同じ保護レベルではない**
- **保持期間。** アップロードされた画像・音声は生成後にただちに削除、選んだモデル提供者側では
  個人データを最大30日保持、と記載されている。**これは個人データの処理説明であって、
  著作物一般についての契約上の保持保証ではない。** そこまで拡張して読まない
- **モデルごとに処理国が異なる場合がある。** 第三者提供者、国際移転、標準契約条項について
  記載がある。案件に国外移転や再委託先の条件があるときは、
  「Magnific を使うか」だけでなく**「Magnific 内でどのモデルを選ぶか」まで確認対象になる**

### Enterprise

- **入力と出力を学習・微調整に使わず、組織内でプライベートに扱う**と Docs に明記
- AI生成された出力について、一定の知的財産の補償を含むと記載

### 判断

クライアントから預かった原稿を入れる先としては、**2026-08時点では Magnific が第一候補。**
通常プランでも画像の学習除外が明記されているのが理由
（→ OPERATIONS.md「クライアント原稿・第三者著作物の入力」）。

ただし、**通常プランが「クライアントの機密を契約上完全に保証する」とは書いていない。**
確認できたのはポリシー上の画像・音声の学習除外まで。入力・出力の全体に契約上の保護が
必要なら Enterprise を検討する。
