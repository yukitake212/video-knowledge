# Higgsfield

2026-08 に公式ブログ・製品ページ・規約で確認。**規約は改定が続いている。都度確認すること。**

## 機能

- **Cinema Studio** — カメラ・ライティング・配置・ショット順を明示制御する制作層。生成の前段に「cinematic logic layer」を置き、LLMに物語の弧・ペース・カメラ論理を先に組ませる設計
- **Cast** — 正面・側面・背面のキャラクターシートを永続アセットとして作る。以降のショットで顔が保たれる
- **Soul ファミリー（画像モデル）** — Soul / Soul 2.0 / Soul Cinema の3モデルと、
  Soul ID・Soul Cast・Soul HEX。→ `models/image/soul.md`
- **Lipsync Studio** — 独立して存在する。動画モデルにリップシンクさせるのではなく専用ツールに投げるのが正しい分担
- **Shots** — 1枚の入力画像から9つのカメラ候補（3×3）を生成するストーリーボード生成機能。
  公式は3:4または4:3の入力を推奨。**Anime & Manga 入力について、2D表現を3Dレンダー化せずに
  新規のアクションアングルへ展開する用途を掲げている**（2026-08-28確認 /
  higgsfield.ai/blog/shots-next-gen-storyboard-generator。公式の製品説明であって
  測定試験ではない）。**絵柄ごとの成功率・線画保持率・スクリーントーンの保持率は公開情報から
  不明**
- **Popcorn** — ストーリーボード生成。フレーム単位の視覚記憶でキャラを保つ。
  単一フレームを独立生成するのではなく**最大8フレームの連続シーケンス**として扱い、
  人物のID・照明・大気を維持する設計。Manual と Auto の2モードがある
  （2026-08-28確認 / higgsfield.ai/creator-hub/help-center/ai-models/how-do-i-use-popcorn。
  製品仕様値）
- 前のクリップを文脈としてアップロードすると、同じ顔・服・環境で次のビートを生成できる
- 顔の入れ替え系は画面に人が1人だけのとき最も精度が高い。複数いると手前の顔が優先される。参照写真と生成先の色温度を揃えると精度が上がる
- MCP・CLI・Supercomputer Agentがあり、Academy（think→set up→generate→test）とClaude Skillも配布されている。**公式Skillの中身は生成API操作**（generate / soul-id / brandkit 等9本、higgsfield-ai/skills）。Seedanceのプロンプト作法は公式ブログ記事のほうで、Skill形式のものは有志製（2026-08確認）

## Higgsfield 上の Seedance 統合

**以下は Higgsfield の統合仕様であって、Seedance というモデル本体の仕様ではない。**
ホストが変われば参照の種類も上限も変わる（→ 下の「ホストによって違う」）。
モデルの挙動仮説は `models/video/seedance.md`。

- **参照を役割別に持てる。** `@character`（人物の同一性）／`@style`（画風・照明）／
  `@motion`（カメラと動き）／`@audio`（音声・リップシンク）。1生成に**最大9画像・3動画・3音声**を
  組み合わせられる（2026-08-28確認 /
  higgsfield.ai/creator-hub/help-center/ai-models/how-do-i-use-seedance。Seedance 2.0）
  - これは `principles/shot-structure.md` の「顔・形は画像参照、動きは動画参照」という
    責任分担が、公式の参照タイプとして実装されている形。**原則は原則側、
    タイプ名と上限はこちら**
- **first-and-last-frame の遷移を作れる。** 前のクリップの最終フレームと次のクリップの
  開始フレームを参照として渡し、その間の遷移を生成する
  （2026-08-28確認 / 同ヘルプ）。構図が2枚とも意図的に決まっている場合に使える
- **Seedance 2.5 は R2V motion guidance を掲げている。** 簡易な人物表現を含む
  モーション参照から動きを移す機能（2026-08-28確認 / higgsfield.ai/seedance/2.5。
  製品ページの記載であって検証結果ではない）
- **Seedance 2.5 の入力上限は「最大50 multimodal inputs」と案内されている**
  （2026-08-28確認 / 同ページ）

### ホストによって違う

同じ Seedance 2.5 でも、ホストごとに案内されている入力の内訳が違う（2026-08-28確認）。

| ホスト | 案内されている上限 | 出所 |
|---|---|---|
| Higgsfield | 最大50 multimodal inputs | higgsfield.ai/seedance/2.5 |
| DomoAI | 30画像・10動画・10音声＝最大50 | www.domoai.app/ai-models/seedance-2-5 |

DomoAI 自体は分業先の候補から外した（→ platforms/candidates.md の履歴は CHANGELOG）。
**この値はホスト差の実例として残す。** 出所を行内に持たせたのは、
参照先のファイルから記述が消えても検証できるようにするため。

**上限や入力種別を「Seedance 2.5 の仕様」として書かない。** ByteDance本体の基礎モデル仕様と
同一かどうかは確認できていない。ホスト統合仕様として、ホストのファイルに書く。

これは `CLAUDE.md` の「プラットフォーム固有の制約を普遍則として書かない」の実例。
過去に「ショット生成は4秒以上」を H3 の制約と気づかず普遍則にした事故と同じ形になり得る。

## プロンプトが内部で書き換えられる

**こちらが書いたものが、そのままモデルへ届くとは限らない**（2026-08 / 二次紹介。未検証）。

- Cinema Studio 内部にプロンプトを強化する仕組みがある
- Supercomputer は依頼から工程を組み立て、適切なモデルへ振り分ける
- ChatGPT 経由の連携でも、依頼の展開とモデル選択が行われる

**含意が2つある。**

**自社のプロンプトの良し悪しを、Higgsfield 経由の出力だけで判断できない。**
書き換えが挟まっているので、効いたのがこちらの記述なのか書き換えなのか分からない。

**書き換え結果を取得できるなら、差分が知見になる。** カメラ用語・音の構造・
環境描写がどう足されるかを複数事例で見れば、そのモデルが何を求めているかが読める。
ただし**取得したプロンプトを public リポジトリへ保存してよいかは利用条件と著作権を
別途確認すること。** 未確認。

## 全部を1つのプロンプトへ詰めない

Higgsfield 自身が、ショットのプロンプトに全部を詰め込まない方向を示している
（2026-08 / 二次紹介）。Seedance 2.5 向けには節に分けた構成を推奨していて、
これは**注意をどこへ割り当てるかの設計**として読める。

モデルごとに別のガイドを持っていることも、**モデルによって書き方が違う**という
こちらの前提と一致する（→ principles/prompt-compilation.md）。

## Cinema Studio 4.0

2026-08 に公開。**制御がプロンプトからUIへ大きく移った。**

内部で使える画像モデルは Soul ファミリー（→ models/image/soul.md）。

### 主な機能

- 1生成あたり **30秒**（3.5 の15秒から倍）
- **最大50画像の参照**
- **30以上のカメラムーブメントのプリセット**
- **2ソースの照明コンソール**
- **50以上のカラーグレーディングのパレット**
- **演技コンソール — 6つの感情 × 3段階の強度**をキャラごとに指定
- 動画の延長（前方・後方・ブリッジ生成）
- モンタージュのペース（Chaotic / Dynamic / Calm / Single Shot）
- 時代セレクタ、ジャンル固有の視覚論理
- **5つのレンズが、後がけのフィルタから生成に組み込まれた光学特性へ**
- 複数モデル対応（Seedance 2.5 を含む）
- パーソナルアシスタント（会話でジャンル・スタイル・カメラ設定を調整し、
  脚本をショットに分解してカメラのパラメータを事前入力する）
- チーム機能（同時生成、要素の共有、Canvas、プロジェクトブリーフ、サブフォルダ）

### 既存則への影響

**`principles/directing.md` と `principles/shot-structure.md` の一部が、
このホストではUIの選択項目になる。**

| 既存則 | Cinema Studio 4.0 では |
|---|---|
| 感情はラベルではなく身体症状で書く | 演技コンソールで感情と強度を選ぶ |
| レンズ数値を書く | レンズが生成に組み込まれた選択項目 |
| 光源と方向を書く | 照明コンソール |
| 色の比率を書く | 50以上のパレット |

**既存則が間違いになるわけではない。** 他のホストでは依然として必要で、
`prompt-compilation.md` の「B. プロンプト外で固定される」に該当する項目が
このホストでは多い、というだけ。

**ただし、UIで指定したことをプロンプトにも書くと二重になる。**
どちらが勝つかは未検証。

### 公式内で仕様が食い違う

**解像度と尺について、3つの公式ソースが違うことを言っている**（2026-08-28確認）。

| ソース | 記載 |
|---|---|
| 製品ページ | ネイティブ4K、1生成あたり最大1分 |

## 契約・データ面

- **通常プランでは入力・出力ともにモデル学習に使われる。** 学習除外は enterprise 契約でのみ契約上担保される
- アカウントや作品を削除すると以後の学習利用は止まるが、既に学習済みのものは取り消せない
- 出力の所有権はユーザーにあり、商用利用も可、解約後も権利は残る。会社側のライセンスはサービス運用目的に限定
- 私的な作品が勝手にマーケティングに使われることはない。使われるのはコミュニティページへの投稿やコンテスト応募など自分で公開したものだけ。**クライアント案件は必ずプライベート領域に置く**
- 公開すると本文まで読まれる。こちらのハウススタイルブロックも公開すれば競合に読まれる
- チームワークスペースでは管理者がメンバーの作品にアクセスできる。権限設計を意識する
- 顔写真からのキャラ作成は生体情報の扱いになる。実在人物の顔を参照に使うのは避けるか、別途の同意を取る
- 規約は2026-08-07と08-27に連続改定された経緯があり、旧規約の永久ライセンス条項が問題になっていた
- 課金面（解約・クレジット消費）への苦情がコミュニティに出ている
- **Enterprise の料金は非公開。** 席数と生成量に応じたクレジット制で、年契約・月払い、と
  案内されている。**最低契約額は公開情報から分からない**（2026-08-28確認 / 公式Enterpriseページ）
- Enterprise では、プロンプト・アップロード・ブランドアセット・生成物をプライベートな
  ワークスペース内に置き、契約上の学習除外を提供すると案内されている。
  ただし**契約書（MSA）・保持期間・再委託先の条件は未確認**

## 判断メモ

- 学習利用の実害は限定的。断片が学習データに混ざるだけで、筋書きが復元される経路はほぼ無い。**エンタープライズ契約の価値はリスク低減より「クライアントに説明できる根拠を持つこと」**
- ただし**クライアントから預かった原稿は別**。実害の大小ではなく、説明できるかで判断する。
  Team / Scale には原稿を直接入れない運用をデフォルトにする
  （→ OPERATIONS.md「クライアント原稿・第三者著作物の入力」）
- Enterprise を契約した場合は、契約書・保持期間・再委託先と案件契約を確認したうえで、
  原稿の入力先候補に戻せる
- プラットフォームの規約より、クライアント契約側の第三者ツール制限のほうが上位。案件ごとに確認する
