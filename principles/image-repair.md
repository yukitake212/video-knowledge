# 画像の修正

出所と時期を各項目に書くこと。2026-08に収集。

**作り直すより直すほうが安い。** ただし直し方には規律が要る。何も指定せずに直すと、
直っていた部分まで変わる。

## 3つを分けて書く

```
WHERE   どこを直すか
WHAT    何に変えるか
PRESERVE 何を変えてはいけないか
```

**PRESERVE が抜けるのが最大の失敗。** 3つ目を書かないと、モデルは全体を作り直す
自由があると解釈する。

OpenAI の公式ガイドは編集の定型をこう書いている（2026-08 / OpenAI Cookbook。**実物確認済み**）。

> **「Xだけ変える」＋「それ以外は全部そのまま」**

そして**反復のたびに PRESERVE リストを繰り返す**。繰り返さないとドリフトする、と明記されている。

Google も「変えないものを明示せよ」で一致（2026-08 / Google Cloud 公式ブログ。実物確認済み）。

### 外科的に直すとき

「それ以外そのまま」では足りない場合がある。OpenAI は、彩度・コントラスト・レイアウト・
矢印・ラベル・カメラ角度・周囲の物を**名指しで**変えるなと書けと言っている。

**曖昧な保護は保護にならない。** 守りたいものを列挙する。

## 作り直す前に専用ツールを検討する

生成モデルに投げるのが常に正しいわけではない。**すでに知られている例：**

- ピクセル一致が要る切り抜きは、生成モデルに頼むと描き直しになる。
  画像ビューアや編集ツールで行う（→ platforms/model-quirks.md、自社検証）
- 背景除去・拡張・アップスケール・文字修正・レイヤー分離には、それ専用の機能を持つ
  プラットフォームがある（→ platforms/higgsfield.md）
- 座標・マスク・矩形での局所編集を公式に持つモデルがある（→ models/image/seedream.md）

**判断の順序：** 専用ツールで済むか → 局所編集で済むか → 全体再生成、の順に検討する。
逆順にすると高くつく。

## 空間の指定手段を使う

テキストだけで場所を指定しない。**「左の椅子」より、マスク・矩形・点のほうが正確。**

モデルによって使える手段が違う（→ models/image/ 各ファイル）。

- テキストによる意味的なマスク指定（どのモデルでも使える）
- 座標・矩形・マスク
- スケッチ・注釈による指示
- レイヤー分離

**手段があるモデルでは、テキストで場所を説明するのをやめる。**

## 局所編集は一括か逐次か

複数箇所を直すとき、2つの方法がある。**どちらが良いかは未検証。**

| | 逐次 | 一括 |
|---|---|---|
| やり方 | 1箇所ずつ直して次へ | 全箇所を1回で指定 |
| 利点 | 各段階で確認できる | 劣化の回数が少ない |
| 欠点 | **回数だけ画質が落ちる** | 失敗すると全部やり直し |

**多段編集は細部が失われていく**という報告がある（2026-08 / 学術研究。自社未検証）。
回数を重ねるほど、直したはずのない部分の情報が落ちる。

## チェックポイントと巻き戻し

多段で直すなら、**承認済みの状態を残しておく。**

```
承認済みマスター
  ↓ 編集1
  ↓ 編集2  ← ここで劣化に気づく
  ↓
巻き戻し：編集2からではなく、承認済みマスターからやり直す
```

**壊れた状態の上に修正を重ねない。** 既存の PATCH LOG の考え方と同じで、
あちらはプロンプトの版、こちらは画像の版（→ templates/shot-schema.md）。

## 修正の評価は2軸で見る

直ったかどうかだけ見ない。

| 軸 | 見るもの |
|---|---|
| 変更 | 頼んだ変更が入ったか |
| 保持 | **頼んでいない部分が変わっていないか** |

**2軸目を見ないと、直った気になって別の破綻を持ち込む。**
特に顔・文字・ロゴ・レイアウトは、変わっても気づきにくい。

## 大きく意味が変わる編集は危険

「色を変える」と「人物を別人にする」は、同じ編集でも難易度が違う。
**意味の階層を大きくまたぐ編集ほど、周囲が壊れやすい**（2026-08 / 学術研究。自社未検証）。

階層をまたぐなら、**編集ではなく作り直しのほうが安いことがある。**

## 高解像度の編集は別問題

高解像度での局所編集は、低解像度とは別の難しさがある（2026-08 / 学術研究。自社未検証）。

**低解像度で編集を確定させてから、最後にアップスケールする**運用のほうが安い可能性がある。
