# ショット構造の原則

出所と時期を各項目に書くこと。根拠が変われば捨てられるようにする。

## プロンプトの骨格

- 責任の分配がプロンプトの本質：顔・形の正解は画像参照、動きの正解は動画参照、空間とカメラの正解は白模型、世界観と優先順位はプロンプトが持つ。プロンプトの仕事は「映像を描写すること」ではなく「素材の役割分担を指揮すること」（自社検証）
- プロンプトの冒頭でショット構造を宣言する：ショット数・総尺・アスペクト比。Higgsfield公式のSeedanceガイドが全フォーマット共通の唯一のルールとして挙げている（2026-08 公式ガイド）
- ただし作業文書型の実プロンプトには「尺・アスペクト・参照モードはUIで設定するので本文には書かない」と明記した例もある。プラットフォームとモードで異なるので実機で確認する（2026-08 corpus/backseat-bleeding）
- プロンプトの型は「品質プリセット行 → シーン全体の要約パラグラフ → 番号付きショット → SFX列挙 → Total行」。全体要約を先に置かないとモデルが各ショットを孤立して解釈する（2026-08 公式ガイド）
- ショットの弧を見出し行に矢印で圧縮して書く（開始 -> 穴を開ける -> 通り抜ける -> 振り返って全体を見せる -> 2体目を倒してレンズに激突）。詳細の前に全体の骨を1行で置く（2026-08 corpus/mecha-bug）
- 「FIRST FRAME (locked)」という見出しで**望む開始構図を文章で記述できる**（2026-08 corpus/mecha-bug）。**ただし実画像の first frame 入力と同じ固定ではない。** 厳密に時刻0の画素を合わせることが MUST なら I2V / FL2V を選ぶ（→ `principles/prompt-compilation.md`「生成モードは『境界』と『再利用』で選ぶ」。2026-08-31 に「画像が用意できないときの代替」から修正）
- 最重要の構造的事実は3箇所で繰り返す。ワンカットであることを Continuity・FORMAT・CAMERA の3つで宣言している例あり（2026-08 corpus/mecha-bug）
- プロンプトの本質は情報量ではなく**制御の階層化**。長いプロンプトは説明が長いのではなく、
  層が分かれている。観察した構成は PREMISE（何のシーンか）→ Reference binding（各参照の役割）
  → LOCKED invariants（絶対に崩さない事実）→ STYLE PREFIX（見た目と物理の法則）
  → ASSETS（辞書）→ ビート列（時間展開）→ SHARED all beats（全ビート共通の再固定）
  → NEGATIVE（失敗モード一覧）（2026-08 corpus/zephyr-cliffhang）
- **末尾に「全ビート共通」の再固定ブロックを置く。** 既存の「最重要の構造的事実は3箇所で
  繰り返す」の一歩先で、ビート別の具体描写で局所最適化したあとに、大域制約をもう一度
  注入する処理として働く。局所記述に飲み込まれた制約を最後に戻す
  （2026-08 corpus/zephyr-cliffhang）
- **スタイルの前置きは美術指定ではなく、世界の振る舞いのプリセット。** 観察した例では
  Lighting / Color ratio / Texture / Camera・Lens / Physics / Continuity / Technical / Audio
  まで入っていた。特に Physics が独立節になっている（2026-08 corpus/zephyr-cliffhang）
- **編集文法を内容と別に固定する節を立てる。** 「単一の連続テイク・4秒・実時間・カット無し」の
  ように、ショットの文法そのものを宣言する。勝手にカットが入ると、接近感・突入感・
  空間の連続性が壊れる。ワンカットは演出趣味ではなく**意味を保持するための制約**
  （2026-08 corpus/creature-charge）
- **空間の記述は二層に分ける。** 地形と街の骨格（どこに何があり、カメラはどの軸を通るか）と、
  被写体の初期配置（第1フレームで誰がどこにいて、どこへ収束するか）を別の見出しにする
  （2026-08 corpus/creature-charge）

## 時間の割り方

- プロンプト内の秒数は必ず0.0sから書く。動画生成AIはカットを横断した時間を記憶できないので、完成タイムライン上の絶対秒をそのまま書いてはいけない（自社検証）
- ただし**秒指定を使うかどうかはモデルによる。** Seedance 2.0 の公式ガイドは
  精密な時間指定を不安定として Shot N の番号方式を推奨し、2.5 は逆に秒単位の
  タイムスタンプを主機能としている。**同じ系列でもメジャーバージョンで反転する**
  （→ models/video/seedance.md）。秒を使う場合の書き方が上の項目
- ショット生成の下限は4秒。4秒未満の秒数指定はしてはいけない。短いカットが必要な場合は4秒以上で生成して編集で切り詰める。**上限はモデル依存なので毎回確認する**（自社検証／上限についてはplatforms/を参照）
- 尺を区間に割り、1区間の主要な動きは1つだけにする。長尺が崩れる典型は後半で指示にない動きに流れること（自社検証）
- 1ショットにつきカメラの動き1つ・被写体の動作1つに絞り、強い具体的な動詞で書く（2026-08 公式ガイド）
- 1ショット内でもビートを割ってよい（0–3.5s 動作に没入 → 3.5–5s ふと止まって正面を見る）。カメラが到着するタイミングと芝居の変化点を合わせる（2026-08 corpus/sofa-scene-2）
- 一部のカットだけ直したいときは、そのカット単独で生成し直す。マルチカットのブロックごと回さない（自社検証）
- **各ビートに終端状態を書く。** 開始動作だけでなく、どういう状態でそのビートを終えるかまで
  書く（「膝が乗る／疲弊した安堵／そこで保つ」）。runaway motion を防ぎやすい
  （2026-08 corpus/zephyr-cliffhang。効果は未検証）
- **ビートの開始は準備からではなく、運動の途中から入る。** ハッチの中で身構えるところから
  始めず、「すでに這い出している途中」から始める。冒頭数秒を準備に使わない
  （2026-08 corpus/zephyr-cliffhang）。冒頭3秒の設計とも一致する（→ principles/workflow.md）
- **超短尺では導入をショットの外で済ませる。** 「第1フレームで既に突進中。空の状況説明
  フレームを置かない」と明示する。4秒しかないショットで、まず街を見せてから敵を出す余裕は
  ない（2026-08 corpus/creature-charge）
- **4秒でも3相に割る。** 接近（0.0–1.5s）→ 交差（1.5–3.0s）→ 通過後（3.0–4.0s）。
  アクションの短尺は setup / collision / exit の3相で設計しやすい
  （2026-08 corpus/creature-charge）
- **長いアクションを複数プロンプトに割るときは、中間安定姿勢で切る。** 観察した例では
  1本目の終点が「相手の脚に一旦乗れた状態」だった。開始姿勢が明確／次へ接続しやすい／
  一枚絵として安定／失敗しても再生成しやすい、の4つを満たす点で切っている
  （2026-08 corpus/zephyr-cliffhang）

### 進行を証明するアングル

アクションのビート分解でアングルを変えるのは、絵のバリエーションのためではない。
**そのビートまで進んだことを誤認しにくいアングル**を選ぶ（2026-08 corpus/zephyr-cliffhang）。

観察した例の5ビート：

1. クローズアップ — ハッチから出る
2. 高いアングルから見下ろす — 登っている（1より少し広い）
3. 低いアングルから見上げる — 登っている＋上から砂粒が落ちてくる
4. 真上からのショット — 相手の脚を掴む
5. 背後からのクローズアップ — 脚の上に乗り移る

同じ「登っている」でも、2は上から、3は下から撮ることで、どこまで進んだかが読める。
**variation ではなく progress proof。**

## 書き方の芯

- 形容詞を積まない。「おしゃれで洗練された」ではなく「MCU、ゆっくりプッシュイン、ハイキー」のように動きとレンズで書く（自社検証）
- 動きに概念名をつけない。名前の解釈幅がそのまま出力の幅になるので、速いか遅いか・雑か丁寧かで書く（自社検証）
- 抽象語は数えられる条件に翻訳する。「最下段」では効かず「開いた引き出しの上に閉じた引き出しが3段見え、下には何もない」なら通る。段数・人数・光源の数・カット数すべてに同じ手が使える（自社検証）
- ただし**高速で交差しブラーのかかる多体では、数を幅で持つほうが実用的な場合がある**
  （「5体か6体」「正確に5体か6体」）。静的で個体が読める対象は数で固定し、
  群衆・群体・敵集団のように読めない対象は**狭い許容幅（bounded count）**で持つ。
  幅の広さは狭く保つこと（2026-08 corpus/creature-charge。自社未検証）
- 速さは「fast」と書かず、観測できる帰結を列挙する。近景は横に流れ遠景はゆっくり動く視差／電柱が走り去る／その影が車内をストロボする／貨物列車を追い抜くので列車が後ろへ流れる／窓の隙間風が髪とネクタイと襟をあおる／ダッシュとクロームが振動する／サスが揺れる／継ぎ目で身体が跳ねる（2026-08 corpus/backseat-bleeding）
- レンズは数値で書く（65mm spherical prime、f/1.4、180°シャッター、~50mm）（2026-08 corpus/sofa-scene）
- 色は比率で指定する。ベース約70%・アクセント約20%・カウンターノート約10%（2026-08 corpus/sofa-scene）
- 実在の撮影監督名を1語のスタイルハンドルとして使う。形容詞を10個積むより短くて正確（2026-08 corpus/sofa-scene）
- ドリフトさせたくない語は文中で大文字にする（LOW / OVER-THE-SHOULDER / ONLY / NOT sharp / SLOW PUSH-IN）。優先順位マーカーとして機能する（2026-08 corpus/sofa-scene-2）
- 譲れない要素を列挙し、優先順位を明示する。全部を守れないときAIが何を捨てるかを自分で決めてしまうため（自社検証）
- 矛盾する指示を混ぜるとAIが片方を勝手に捨てる。「close-up／画面いっぱい」と「全身を見せる」の併記で足が切れた実例あり（自社検証）
- ACTION TIMING の末尾に Physics 節を置き、重量・慣性・反動・落下を列挙して「nothing floats」で締める。AI動画の浮ついた動きはここで潰す（2026-08 corpus/mecha-bug, backseat-bleeding）
- **空間事故はディテール不足ではなく、位相関係の不足で起こる。** 複数の物体が絡むシーンでは、
  物の説明より関係の記述が効く。上／下／逆さ／片脚を下へ伸ばす／そこを登る／その脚を掴む、
  のように**関係のネットワーク**として書く。多物体シーンでは identity lock より
  topology lock のほうが重要な場合がある（2026-08 corpus/zephyr-cliffhang）
- **同種の物体を2つ出すときは4軸で固定する。** 色（palette）・形（silhouette）・
  位置（topology）・物語上の役割（narrative role）。観察した例では2体のメカを、
  白/からし/えんじ・箱型・下・逆さ・主人公が出てくる側／濃紺/黄・猛禽型の鉤爪脚・上・
  片脚を下ろす・主人公が掴む側、として区別していた。色だけでは取り違える
  （2026-08 corpus/zephyr-cliffhang）
- **色の比率指定は、多参照シーンの優先色管理でもある。** 既存の70/20/10は look の話として
  書いてあるが、複数の参照が持ち込む色（衣装のえんじ、メカのからし、別のメカの濃紺と黄、
  錆びた鉄）をそのまま強く出すと画面の色が散る。どれを主・従にするかを比率で決める
  （2026-08 corpus/zephyr-cliffhang）
- **質感の列挙は解像感のためではなく、力がかかっている証拠として書く。** 落ちてくる砂粒＝
  上で何かが崩れている、汗と吐く息の白さ＝身体が限界、帯の唸り＝張力がある、機体の揺れ＝
  質量がある。アクションでは質感は装飾ではなく **force evidence**
  （2026-08 corpus/zephyr-cliffhang）
- **そのショットに出ない参照は、最終プロンプトから消す。** 案件ヘッダに全アセットがあっても、
  **全件を貼らない。** `@tag` をその物が居ないショットに置くと、
  **モデルはそれを画面へ押し込もうとする。**
  **参照の一覧ではなく、このショットで画・音・動作に寄与するものだけを出力する**
  （2026-09-02 / 公開Skill。未検証。→ `guards.md`「文脈を持ち込まない」）
- **参照に写っている細部も、言葉で書く。** 小さな文字・ロゴ・色は、
  **参照画像にあってもモデルが落とす**（2026-09-02 / 公開Skill。未検証）
- **人物の説明は最小限にする。長い外見描写は参照画像と衝突して、参照のほうを劣化させる**
  （2026-09-02 / 公開Skill。未検証）
- **画角は名前ではなく、その画角が生む幾何効果まで書く。** 「84度の広角」だけでなく、
  近づくと巨大に見える／通り過ぎるとフレーム端へ伸びる／街路が広がって見える／
  ただし魚眼にはしない、まで書く（2026-08 corpus/creature-charge）
- **カメラの高さは効果で書く。** 地上0.5mに置くと、床面の速度感・瓦礫との接触・脚の暴れ方・
  すれ違う身体の近さが出る。単なるローアングルではなく**低い位置を通る軌道**
  （2026-08 corpus/creature-charge）
- **カメラの乱れを欠陥ではなく質感として設計する。** 強い手持ちの揺れ、方向性のあるブレ、
  ホイップパン、行き過ぎて戻す修正、ジンバルのように無菌ではない、ドローンのように
  浮かない。危険な対象に突っ込んだときの**操作者の失敗の痕跡**まで書く
  （2026-08 corpus/creature-charge）
- **モーションブラーは破綻隠しであると同時に、速度の主要表現でもある。** 複雑な形状が
  至近で高速に交差するショットでは、形を完全に見せるより「近くを高速で通り過ぎる体感」を
  優先してよい。精密描画の難しさを運動表現へ逃がしている
  （2026-08 corpus/creature-charge。推測を含む）
- **被写体の行動とカメラの行動を同格に設計する。** 「敵が走る」ではなく「走ってくる敵群の
  中にカメラが突っ込む」。アクションではカメラの侵入経路そのものが主題になり得る
  （2026-08 corpus/creature-charge）
- **複雑なデザインの被写体では、デザインの完全な読解より体験価値を優先してよい。**
  観察した例が作っているのは、向かってくる／すり抜ける／圧がある／近すぎる／埃だらけ／
  視界が乱れる、という体感。そのために導入・中央構図・クリアな視認性・安定したカメラ・
  シルエットの読みやすさを一部捨てている。**一枚絵的な良さを削って運動体験に変換する**
  （2026-08 corpus/creature-charge）
- プロンプトの最後に `END.` を置いている例がある。台詞を続けない・行動を継続しすぎない・
  余計な展開に行かない、ための終端合図として機能している可能性がある。
  **推測。検証していない**（2026-08 corpus/mech-cockpit-dyad）

## 参照の扱い

- 参照ごとに「使う情報」と「使わない情報」を書く（例：この動画から動きだけ取り、場所と服と人物は取るな）（自社検証）
- 参照は「同一性の土台」であって「同一性の保証」ではない。外見の記述を全部削って参照だけに委ねると造形が流れるので、最小限の識別特徴は文章でも重複記述して保険にする（自社検証）
- **参照から不要な属性を継承させないときは、否定だけでは足りない。** 「参照は顔の同一性だけを支配する。参照写真の髭・髪型・服は継承しない」と否定したうえで、置き換えを全部肯定形で埋める。空白を作ると参照が埋め戻してくる（2026-08 corpus/backseat-bleeding）
- 参照素材に写り込んだ不要物（額に上げたサングラス等）は Standing note として版をまたいで持ち越し、毎回ロックし続ける（2026-08 corpus/backseat-bleeding）
- 参照は必要な属性だけに絞ってよい。顔を隠す芝居なら「体格・肌の色・姿勢・佇まいだけを参照」（2026-08 corpus/bank-heist）
- @Image番号は生成ごとのスロットであって永続IDではない。台帳で毎回定義し直す（2026-08 corpus/sofa-scene, sofa-scene-2）
- 場所も@参照にする。同じ部屋の対向する壁を main face / reverse face として2枚渡すと、切り返しのイマジナリーラインが破綻しない（2026-08 corpus/sofa-scene）
- 各アセットに「100% matches the reference」と忠実度を明示的に要求する（2026-08 corpus/mecha-bug）
- ショット途中で変化する属性は3箇所で押さえる：STATE LOCK（開始状態）／ACTION TIMING（変化の瞬間）／PHYSICS（変化の物理法則）（2026-08 corpus/backseat-bleeding）
- **参照の管理単位は「画像」ではなく「役割つき画像」。** 観察した例では各参照に
  look anchor / first frame anchor / 物体の同一性 / 人物の同一性 / 場所の連続性 という
  役割ラベルが付いていた。さらに `load in this order` と読み込み順まで指定されている
  （順序が効くかは未検証）（2026-08 corpus/zephyr-cliffhang）
- 参照の役割は5つに分けられる：**identity**（人物）／**set**（室内・物理空間）／
  **light motivation**（外光・天候）／**interaction object**（操縦桿など触る物）／
  **look**（トーン全体）。同じ画像でも用途が違えば支配範囲が違う
  （2026-08 corpus/mech-cockpit-dyad）
- **`only` を付けて支配範囲を明示的に閉じる。** 観察した例では場所参照に
- **参照どうしの優先順位を決める。** 支配範囲を閉じても、**2つの参照が同じ属性を主張したら
  どちらが勝つか**は決まらない。参照ごとに**何の権威か**を1つ書く
  ——「画風はこの参照」「同一性はこの参照」「位置はこの参照だけ」。
  **添付の順序も効く。写真参照を先、図式や補助を最後**（→ `templates/lock-blocks.md`。
  2026-09 / 外部情報。**自社未検証**）
- **`only` を付けて支配範囲を明示的に閉じる。** 観察した例では場所参照に
  「地形・素材・大気・光の方向のみを支配する」と書いてあった。参照は使うだけでなく、
  **何を支配させないか**まで書く（2026-08 corpus/creature-charge）
- **場所の参照は、その場所を映さずに光だけ持ち込む用途にも使える。** 屋外が一切見えない
  室内カットで、外の場所を light reference として渡すと、光・色温度・天候・状況の連続が
  室内に入る（2026-08 corpus/mech-cockpit-dyad）
- ヒーロースチル（決め画1枚）は、構図・グレード・幾何配置の三役を同時に担わせられる
  （2026-08 corpus/zephyr-cliffhang）

### アセット方式とファーストフレーム方式

**この2つの間に、もう1段ある。**

| 手段 | 固定するもの | 残る自由度 |
|---|---|---|
| **文章のブロッキングだけ** | 言葉で書いた配置 | **構図の自由度は高い。配置の精度は低い** |
| **配置図（中間）** | **位置・姿勢・向きだけ** | 見た目とカメラの自由度は残る |
| **完成ファーストフレーム** | 画素配置まで | **自由度は最も低い** |

**中間が効くのは、複数人物・什器・中央通路・左右対称が絡む画。**
実案件で**人物が塊化し、椅子が湧き、モブの造形が崩れた**カットは、ここに該当する。

**配置図の作り方（構造だけ。原文は写していない）。**

- **元フレームは構図だけの正本。** 写真的な見た目は取らない
- **カメラ側から見た正面図。真上からの平面図にしない**——動画モデルはフレームで考える
- **クロップされた身体は補完しない。** フレーム端で切れているなら図でも切る
- **人物は塗りではなく、色違いの細い輪郭。** 塗りは画風として漏れる
- **図に文字を入れない。** 記号は色で持ち、**A/B/C はプロンプト側のテキストだけに置く**
- **支配範囲を肯定形で閉じる。** 「見た目・光・衣装・顔は場所と人物の参照から。
  配置図は位置だけ」。**否定形で「図の画風を使うな」と書くと、その語を召喚する**
- **配置図は最後に添付する。** 写真参照を先に置く
- **直すときは、前の図からではなく元フレームから作り直す。**
  図を入れ直すと、図の欠点を写し始める

**`principles/world-assets.md` の「空間の見取り図」とは役割が違う。**
あちらは**世界の永続的な地理で、文字で持つ。** こちらは**一つのカメラから見た
一ショット内の配置で、画像で持つ。**

**方法の考案者に権利がある。** 構造だけを取っている。（2026-09 / 外部情報。AI短編の公開プロジェクトから**構造だけ**を抽出。本文は写していない。
**自社未検証**）


公開プロンプトを5本分解した結果、**composed な開始画像を渡しているものは
1本も無かった**（2026-08 corpus/全6本）。渡しているのは人物カード・場所カード・
物体カードで、それぞれが独立しており、**構図はプロンプトが作っている。**

両方式の差：

| | アセット方式 | ファーストフレーム固定 |
|---|---|---|
| 画像生成の回数 | 案件全体で3〜7枚 | カットごとに1枚 |
| 再利用 | 全カットで使い回せる | 1回きり |
| カメラの自由度 | 大きく動かせる | そのフレームから動くだけ |
| 構図の保証 | プロンプト次第 | 確実 |

**開始フレームを固定すると、カメラはそのフレームから動くことしかできない。**
ある案件で全カットが「静止」か「わずかにプッシュイン」ばかりになったのは
これが原因だった（自社の失敗）。公開プロンプトにクラッシュズーム、通り抜け、
ウィップパン、振り返っての全景リビールが入っているのは、構図を固定していないから。

**解：開始構図を文章で書き、画像では固定しない。**
`FIRST FRAME (locked)` という見出しで開始構図を文章で書く方式が実際に使われている
（2026-08 corpus/mecha-bug）。構図の意図は伝わり、カメラはそこから自由に動ける。

**ただしこれは「固定」ではなく「記述」。** 文章の見出しは実画像の first frame 入力と
等価ではない。**時刻0の画素配置そのものが MUST なら I2V / FL2V を選ぶ**
（→ `principles/prompt-compilation.md`。2026-08-31 に限定）。

**構図そのものが要点のカット**（テロップカード、書影、特定の俯瞰構図）では、
画像で固定するほうが確実。**Ref2V で `<Picture>` を構図アンカーに使っても、
出力の第1フレームがその画像になる契約ではない。**

### カメラの動きは、速度と終端状態の両方を書く

**片方だけだと極端に振れる。**

「一定速度で止まるな」と書いた結果、**5秒でクローズアップまで移動しきった。**
その前は「早く終わるな」と書いて**運動が終盤に押し込まれた。**

**時間についての指定は、量とセットにしないと両方向へ振れる。**

終端状態の書き方の例——「**最後のフレームでも参列者が下三分の一を占めていて、
中心の対象はまだ小さい**」（2026-08-31 / 自社検証・複数回）。

### 画角は離散値のアンカーから選ぶ

**公開Skillが、度で書く9段の表を持っている。**「23° と書くな。18° か 29° にしろ。」

| FOV | mm相当 | 用途 |
|---|---|---|
| 180° | 魚眼 | POV、夢 |
| 107° | 14–16 | 超広角、巨大な内観 |
| 84° | 20–24 | 広角、群の配置 |
| 63° | 28–35 | 観察・ルポ |
| 47° | 40–50 | 中立、人間の視覚 |
| 29° | 75–85 | 対話のバスト |
| 18° | 100–135 | 近接ポートレート、**同一性が保たれる** |
| 12° | 180–200 | 手・物のディテール |
| 8° | 300–400 | 極端な圧縮、遠くからの観察 |

**mm は書く側が寸法感を掴むためのもので、プロンプトには度で書く**——というのが向こうの主張。
**うちは corpus 由来で「レンズは数値で書く（65mm spherical prime、f/1.4）」を持っている。
どちらも公開プロンプト1本が根拠で、割れている**（→ `OPERATIONS.md`「割れている論点」）。

**この表には2つ穴がある**（2026-09-02 / 指摘を一次情報で確認）。
**センサーサイズを定義せずに FOV と mm を対応させている**ので、
mm 側の数値は特定のフォーマットを暗黙に仮定している。
また `low-angle 18°` のように、**画角の度と俯仰角の度が同じ単位で混ざる**書き方が
同じ文書内にある。**度で書くなら、どちらの度かを毎回明示する。**

**マルチショットではセグメントごとに FOV を指定し、`no drift mid-segment` を足す。**

**極端な画角（8° / 107°）のマルチショットは4つ全部が要る**——場所参照を全ビートで統一／
各ビート冒頭で FOV を明示／各ビート末尾で FOV を確認／色は素材と光で書きリストにしない。
**欠けると2〜3ビートで崩れる。**

### カットの精度は4段階から選ぶ

**二択ではなく、必要な精度を選ぶ。**

| | 書き方 |
|---|---|
| **ワンショット** | 「連続した1ショット。カメラは自分でカットしない」 |
| **順序だけのカット** | `CUT 1 … CUT 2 … CUT 3` を順に記述。**秒は指定しない** |
| **秒指定のマルチショット** | 明示的な HARD CUT を秒で置く |
| **フリースタイル b-roll** | カットを固定せず、アングルはモデルに探させる |

**内部カットをまたいで保持するもの**——同じ人物集合、同じ幾何、スクリーンディレクション、

### カメラは、機械の仕様でも人格でも書ける

**「誰が、どういう状態で撮っているか」で書くと、複数の属性が一度に決まる。**

### 「1ショットにつき動き1つ」は、画面全体で1つという意味ではない

**映っている人物・動物・物すべてに演出を書く。カメラワークと芝居はトレードオフではない。**

### 被写体にタスクを与える

**「立っている」「見ている」は状態であって行為ではない。**

台詞のないカットで状態と微細な挙動しか書かないと、画が動かない。
**歩く・屈む・掲げる・沈む**といった行為を先に決めると、
**動きの要求がそこへ吸われるので、他の要素（顔・持ち物）が安定する。**

### 座標系を4つに分ける

**「銃の左側」は frame-left と読まれる。** 弾帯が両側に出た実例がある。
**「カメラに近い側」と書き直したら直った。**

**左右・前後・遠近を書くときは、どの座標系かを毎回明示する。**

| 座標系 | 書き方 | 使う場面 |
|---|---|---|
| **画面** | `screen-left` / `screen-right` | 配置、動きの方向、繋ぎの方向 |
| **カメラ相対** | 「カメラに近い側」／「向こう側」 | 物の面、遮蔽、前後関係 |
| **人物の解剖** | 「その人物の左手」 | 身体の動作 |
| **物体固有** | 「銃口側」／「銃床側」 | 物の向き |

**混同の既定値は「画面」。** だから物体固有で書きたいときほど明示が要る。

### 長い1ショットは、難度を時間で配る

**30秒のワンショットが、公開クリップとして成立している。**
成立しているのは3人を上手に生成したからではなく、**難しいものを後ろに置いたから。**

| 秒 | 見せているもの | 難度 |
|---|---|---|
| 0–6 | 足元、雪、履物 | **低い。顔なし・手なし・接触なし** |
| 6–12 | 胴体、三者の移動 | 中。全身の関係が要る |
| 12以降 | 後頭部と横顔、感情演技 | **高い** |

**カメラの上昇が、そのまま難度の投入順になっている。**
顔を最初から背負わせず、**身体の関係が安定してから顔を足している。**

カメラの動きは格好よさのためではなく、**情報の開示順であり、同時に難度の投入順。**

**演技の負荷も均等に配らない。** 3人いるが、**演技が書かれているのは1人だけ。**
残り2人は「握りは固く事務的」「動じずに歩き続ける」で**単純で同じ仕事**しか持たない。
**映る全員に演出を書く**という原則とは矛盾しない——**全員に書くが、難度は集中させる。**

**全体の運動ベクトルを1つにする。** 前進方向とカメラの上昇方向が一貫している。
複雑な多人物の芝居でも、**運動の向きが1つなら長く持つ。**

## カメラモーションとVFX

Higgsfieldは50以上のカメラモーションプリセットを持つ（2026-08確認）。
プリセットはアプリ側で選び、プロンプト内でも名前を書く。

用途で分けた主なもの：

- **移動・接近**：Dolly In/Out/Left/Right、Super Dolly、Crash Zoom In/Out、
  Rapid Zoom、Dolly Zoom（めまいショット）、YoYo Zoom
- **回り込み**：360 Orbit、Arc Left、Lazy Susan、Bullet Time
- **通過・侵入**：Eyes In（目に入る）、Mouth In、Through Object In/Out、
  Flying Cam Transition
- **視点**：Object POV（物の視点）、Snorricam（体に固定）、Hero Cam、
  Head Tracking、FPV Drone
- **その他**：Focus Change、Whip Pan、Dutch Angle、Fisheye、Low Shutter、
  Robo Arm、Handheld、Static

VFXは別レイヤーで、モーションと組み合わせてショットの途中で変化を起こせる
（クラッシュズームしながら人物が金属に変わる、など）。

### 規律

- **大きな動きは1クリップに1回だけ。** 派手なプリセットを使いすぎると効果が死ぬ
  （2026-08 複数の公式・解説記事で共通）
- 主モーションを1つ決めて、副次的な動きを薄く足す
- 相反する動きを混ぜない（Dolly In と Dolly Out の併記など）
- **効果には、それが起きたと分かる物理を書く。** バレットタイムなら宙に浮いた
  水滴や火花を数えて描写しないと、時間が止まっていることが画で読めない。
  「抽象を数えられる条件に翻訳する」がここでも効く

### 通過・変質系の技法

挙がっていた「人物の目に入っていくカメラ」「弾道を追う回り込み」などは、ほぼ
プリセットとして名前が付いている。

- **Eyes In / Mouth In** — 目や口に入っていく
- **Through Object In / Out** — 物体を通り抜ける
- **Bullet Time** — 被写体が静止したまま180度回り込む
- **Object POV** — 物の視点
- **Flying Cam Transition** — 飛行による転換

VFXは別レイヤーで、モーションと組み合わせて**ショットの途中で変化を起こせる**
（クラッシュズームしながら人物が金属に変わる、など）。

**バレットタイムのコツ**：宙に浮いた粒子（水滴や火花）を数えて描写しないと、時間が
止まっていることが画で読めない。「抽象を数えられる条件に翻訳する」がここでも効く。
