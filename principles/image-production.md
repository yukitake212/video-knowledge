# 画像制作の工程

出所と時期を各項目に書くこと。2026-08に収集。

**画像は「アセット作成」1工程では粗すぎる。** 何を作っているかで、使うモデルも、
制御の手段も、評価軸も変わる。

`principles/prompt-compilation.md` の画像版。あちらの原則（最終プロンプトは成果物、
情報の4分類、MUST/SHOULD/MAY、組み立ては複数回）はそのまま効く。

## 何を作っているかを先に決める

12に分ける。**この分類をしないと、同じ「画像を作る」という理由だけで
別々のモデルを同列比較してしまう。**

| # | タスク | 何が最重要か |
|---|---|---|
| A | 探索・ルック開発 | 幅。正解を絞らない |
| B | キャスティング・同一性の確立 | 顔の確定 |
| C | キャラクターシート | 同一性の保持 |
| D | 物・小道具アセット | 再現性 |
| E | 世界・環境アセット | 空間の一貫性 |
| F | ヒーローフレーム・ショット用の画 | 構図と動画への渡しやすさ |
| G | 別アングル・多視点 | 同一空間だと読めること |
| H | 局所修正 | **変えない部分を壊さないこと** |
| I | 全体編集・リライト・材質変更 | 同上 |
| J | レイヤー分離・クリーンプレート | ピクセルの整合 |
| K | 文字・図版が主のもの | 可読性 |
| L | 動画への受け渡し | 動かせる画になっているか |

**HとIとJは「編集」で、生成とは別の規律が要る**（→ principles/image-repair.md）。
**EとGは世界設計**（→ principles/world-assets.md）。

## 探索と本番を分ける

同じモデルでも設定が変わる。**混ぜると、探索なのに絞られ、本番なのに散る。**

| | 探索 | 本番 |
|---|---|---|
| 目的 | 方向を見つける | 決めたものを出す |
| 候補数 | 多く | 少なく |
| 制約 | 緩く | 固く |
| 参照 | 少ないか無し | 全部 |
| 評価 | 面白いか | 仕様どおりか |

これは既存の Think工程と本番の区別（→ principles/workflow.md）を、画像側へ広げたもの。
**探索で全参照を渡すと、既知のものしか出てこない。**

## 制御はプロンプトだけではない

画像側では、指示を渡す経路がテキスト以外へ大きく分散している。

```
テキストプロンプト
同一性の参照 / 物の参照 / スタイルの参照
ムードボード
学習させた同一性（LoRA・トレーニング済みID）
マスク / 矩形 / 点 / 投げ縄
スケッチ / 注釈
レイヤー
カラーパレット
カメラのUI / 照明のUI
APIのハードパラメータ
プロバイダ側のプロンプト書き換え
```

**どの経路が最適かはタスクとモデルで変わる。** プロンプトに書くのは、
他の経路で担保できないものだけ（→ principles/prompt-compilation.md の情報4分類）。

`prompt-compilation.md` の「B. プロンプト外で固定される」は、当初は尺とアスペクト比の
想定だった。**画像側では上のリスト全部がBに入る。** そして 2026-08 時点で、
Cinema Studio 4.0 のように**感情・照明・色・カメラをUIへ外出しする方向**が進んでいる
（→ platforms/higgsfield.md）。

## 最終プロンプトは原本ではない

原本は、タスクごとの構造化された仕様。プロンプト・参照・マスク・ムードボード・UI設定・
APIパラメータは、そこから派生する成果物。

**モデルを変えるとき、前のモデル用のプロンプトを手直ししない。** 仕様まで戻る。

## 画像の3分類

同じ「良い画像」でも、目的によって良さの定義が違う。

| 種類 | 何のための画か | 良さの基準 |
|---|---|---|
| 証拠アセット | 何が存在するかを固定する（顔・物・場所） | 情報が読めること。美しさは二の次 |
| 方向アセット | どういうトーンかを共有する（ルック・ムードボード） | 方向が伝わること |
| 最終フレーム | そのまま映像になる | 画として成立し、かつ動かせること |

**証拠アセットを綺麗に作りすぎない。** 顔のクローズアップに強いボケや劇的な照明を
入れると、情報が減って参照として弱くなる。既存のシートが無地背景・均一照明なのは
そのため（→ templates/character-sheet.md）。

## 動きやすい画という評価軸

**画として美しいことと、動画の起点として良いことは別**（2026-08 / 推測。未検証）。

動かしにくくなる要素の候補：

- 強い浅い被写界深度。奥行きの情報が失われるので、カメラが動くと破綻しやすい
- 極端に凝った一枚絵。情報が多いほど、動かしたときに壊れる箇所が増える
- 完全な静止・完全な対称。動きの手がかりが無い

既存の「開始フレームを固定すると、カメラはそのフレームから動くことしかできない」
（→ principles/shot-structure.md）と対になる。**フレームを作る段階で、
その後の自由度を決めている。**

**未検証。** 検証するなら、同じ被写体を「凝った一枚絵」と「情報を抑えた画」で作って、
同じ動画プロンプトに渡して比べる。

## 知見が増えてもプロンプトは長くならない

Krea は公式のプロンプト拡張用システムプロンプトで、**「既に詳しいプロンプトは、
大きく膨らませず軽く磨いて仕上げる」「入力が支持していない限り、具体的な服・色・素材・
場面の細部を発明しない」**と自社の拡張器に指示している
（2026-08 / krea-ai/krea-2 公式リポジトリ `docs/expansion.txt`）。

**モデル提供元が、自分の拡張器に対して過剰な指定を禁じている。**
既存の「知見が増えてもプロンプトは長くならない」と同じ思想
（→ principles/prompt-compilation.md）。
