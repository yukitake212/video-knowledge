# 静止画素材を動かす

> **これは案件全体の条件。** 素材が完成した静止画（漫画原稿・書影・挿絵・キャラクターシート）
> なら、画像を作る工程とプロンプトを書く工程の**両方**で参照する。→ `skill/SKILL.md`

出所と時期を各項目に書くこと。**このファイルはほぼ全部が自社未検証。**

完成した静止画を素材として動かすときの原則。書影、挿絵、提供写真、漫画原稿、
先に確定させたキャラクターシートやタイトルカードなど。**最も制約が強いのは漫画原稿**なので、
以下では主たる例として扱う。

## 素材の物理仕様を先に測る

**作業に入る前に、素材の解像度・ビット深度・網点線数を実測する。** これだけで出力解像度・
ズームの上限・モアレの発生域が算術で決まり、後の判断が推測でなくなる（2026-08 / 自社検証。
1冊の校了PDFで実測。`pdfimages -list` と、トーン領域のFFTによる網点周期の測定）。

実測した1件：頁 3113×4601px・600dpi・1bit・網点60線。ここから計算だけで出た結論。

| 問い | 答え | 出し方 |
|---|---|---|
| 1080×1920 の等倍クロップは頁のどれだけか | 34.7% × 41.7%（およそコマ1つぶん） | 1080/3113、1920/4601 |
| ページ全体からの寄りはどこまで拡大補間なしか | 2.88倍 | 3113/1080 |
| 4K縦（2160×3840）は成立するか | **しない** | 幅を2160に合わせても高さが3193pxしか出ない |
| 網点1セルは何pxか | 10.06px（公称10.0） | 600dpi ÷ 60線。実測はFFT |

**効くのは下2つ。** セル幅が分かるとディスクリーンに要るガウスの σ が決まり
（→「網点素材の縮小」）、拡大の上限が分かると寄りを素材段階で作るか編集で寄せるかが決まる
（→ 次節）。

**代表ページだけ見て仕様を決めない。全ページを走査する。** 152ページの校了PDFで
**1ページだけ絵柄の解像度が半分**だった（他が 3113×4601 のところ 1557×2301）。
**そのページを使うカットだけ、寄りの上限が変わる。** 同じ走査で本文ページが
ラスタではなくベクターであることも分かった——制約ではなく利点で、解像度が自由になる
（2026-08-28 / 自社検証。`pdfimages -list` で全77PDFページを走査。
手順は `OPERATIONS.md`「生成結果と素材を測る」）。

## 素材はショット設計済みのアンカー

完成した静止画は、人物配置・ポーズ・画角・照明・衣装・背景・感情のビートを**すでに含んでいる**。
だから「何が映っているか」を書き直すのは無駄で、**足す動きだけを書く**
（2026-08 / 外部の実務記事。elser.ai、2026-08-05。自社未検証）。

これは `principles/shot-structure.md` の「構図そのものが要点のカットでは
ファーストフレーム固定が有効」の適用例。**素材がある場合、構図の要点は素材側にある。**

同ファイルの「開始フレームを固定すると、カメラはそのフレームから動くことしかできない」も
同時に効く。素材を渡す以上、カメラの自由度は最初から制限されている。
**それを承知で選ぶ**のが、この方式。

**さらに、素材を最終解像度で作ると編集側のズーム余地もゼロになる。**
1080×1920 の台紙に落とした素材を編集で寄せると、等倍であってもアップスケールになる。
寄りが要るなら**寄り用のクロップを素材段階で別に作る**。固定フレーム＋微動に振った案件では
素材を1枚増やすコストがほぼゼロなので、そのほうが線もトーンも出力解像度でジャストになる
（→ platforms/model-quirks.md。生成側にカットを割らせる方針とは逆になる）。

**ただし、消えるのは編集側の自由度だけ。** 素材を最終解像度に落としても、**生成側で
カメラを動かすことはできる**（H3で確認。→ `platforms/model-quirks.md`「カメラを動かしても
縦横比は壊れない」）。したがって「寄り用のクロップを別に作る」は唯一の手ではなく、
**寄りを編集で持つか生成で持つかの選択**になる。編集で持つなら別クロップ、
生成で持つならカメラ指定。

### ただし、見せ場では書き直す価値がある場合がある

上の「足す動きだけを書く」は工数の原則としては正しいが、**「静止画が動く」こと自体が
商品になっている案件の見せ場**には当てはまらないことがある。原稿が最も良い瞬間を1枚で
描いているなら、その瞬間を映像として展開すること自体が納品物の価値になる。
原則を機械的に適用すると、**一番動かすべき場所を避ける**ことになる。

**（2026-08 / 推測。未検証。1案件での判断であって、視聴データや先方評価による裏付けはない）**

「動きを足す量」と「どの1カットに投資するか」は別の軸として持つ。

## 素材をそのまま渡さない

工程を分ける（2026-08 / 外部の実務記事。自社未検証）。

1. **必要な部分を抽出する。** ページ全体・見開き・素材一式をそのまま渡さない
2. **余白を拡張し、clean plate 化する。** 文字を除いた状態を作る
3. **1ショット単位の参照に変換する**
4. **絵を再説明せず、追加する動きだけを書く**

工程を分ける理由は、構図・画風・人物を**個別に管理できるようにするため**。
一括で渡すと、どれが崩れたのか切り分けられない。

## 原作からの距離を3段階で決める

どこまで動かすかを企画段階で決める。**クライアントとの合意事項になり得る**
（2026-08 / 推測。外部の Motion comic / Panel-inspired animation の区別を手掛かりに拡張）。

| 段階 | 素材の扱い | 動き |
|---|---|---|
| 保持＋カメラのみ | そのまま | pan / zoom / パララックス |
| 保持＋微動 | そのまま | 人物と環境の少数の微動 |
| 素材を起点に離れる | 起点として使う | 新規アングル・完全なアニメーション |

**一様にしない。** 素材そのもの・微動・枠を越える・完全な動き・素材へ戻る（freeze back）を
混在させると、「素材であること」と映像的な驚きを両方残せる可能性がある
（2026-08 / 推測。実証データなし）。

### 各ショットは2軸で決める

**素材への忠実度**と**運動量**を別の軸として持つ。全ショットを一様に動かすより、
演出の幅を管理しやすい（2026-08 / 推測）。

素材のまま → 微動 → 部分的な動き → 完全な動き → 素材へ戻る、という往復も同じ軸で書ける。

## 演出パターン

### 生きている下限だけを足す

線・トーン・構図を維持し、瞬き・呼吸・髪・煙・雨・服の裾・光など**少数の微動だけ**を足す。
素材らしさを残したまま、動画としてのフックを作る
（2026-08 / 推測。`principles/directing.md` の「生きている下限」を静止画素材へ適用して導出）。

**足す動きの数を先に決める。** 3つまで、のように上限を置くと、
素材の質感が保たれる可能性が高い（未検証）。

### 枠を越えて空間化する

素材から始め、カメラが一部へ寄る → 線と質感を保ったまま奥行きと微動が発生 →
枠が画面外へ消える → 素材にないカメラ位置へ移行。
**素材であること自体をフックにする**（2026-08 / 推測。未検証）。

**発生の描写と枠の突破を、同じカットに詰めない。** 「何かが起きる」描写と「枠を越える」
描写を1本の生成に同居させると、モデルが両者を**因果として結びつける**ことがある。
人物が枠外へ出る動きと周囲のコマが退場する動きを同じ文の流れで書いたところ、
**人物が周囲のコマを押しのけているように解釈された**（2026-08 / 自社検証・H3で1回。
他モデルで同じかは不明）。

対処は2つ。**記述上で因果を切る**（「何も押していない、ただ移動して退場する」と明示）か、
**カットを分ける**。

### 段階的に起動させる

完全な動きへ移すとき、一発の morph ではなく**運動の自由度を段階的に増やす**。
瞳だけ動く → 髪や背景の現象が動く → 奥行きが生じる → 枠が消える →
カメラが素材にない位置へ動く（2026-08 / 推測。未検証）。

### 2枚の間を補間する

連続する2枚を始点・終点の視覚アンカーとして扱い、**素材では省略されている中間動作**
（振り向き、手の移動、接近）を生成する。カメラの移動だけの演出より自由度が上がる。

first-and-last-frame の遷移機能を持つモデルがある（→ platforms/higgsfield.md）。
**モデル固有機能なので普遍則として書かない。**

**中間は取れるが、終点への着地は取れない。** H3のFL2VAで版面の異なる2枚を繋いだ3回とも、
運動そのものは生成されたが最終フレームへは連続運動で到達せず、最後に1〜2フレームで
ジャンプした。懸念していたクロスフェードや溶けるような変形は3回とも起きず、
線と網点は保たれた。**限界は「運動が描けない」ではなく「終点に着地できない」という形で出る**
（2026-08-28 / 自社検証・1案件3回。→ `platforms/model-quirks.md`）。

したがって、**決めポーズや特定の版面への着地は生成に任せず編集で持つ。** 原稿のコマを
静止画として編集で繋げば、繋ぎ目は編集のカットになる。これは生成内のモーフィングとは
質が違い、**打点として演出に組み込める**（下の「素材へ戻る（freeze back）」と同じ扱い）。

### 発生を描くなら、発生前の絵を探す

I2Vは第1フレームから先へ展開するので、**素材にすでに完了した出来事が描かれていると、
そこへ至る過程は遡って生成できない。** 「飛び出した直後」が描かれたコマへ
「飛び出してくる」と指示したところ、モデルは**人物を巨大化させることで応えた**
（2026-08 / 自社検証・H3で1回。外へ出る量を増やす手段がスケールしか残っていなかった
ためと考えられる）。

発生を描くなら、**発生前の状態を第1フレームとして別に用意する。** 原稿の別ページに使える
絵があればそれを使う（塗りつぶしが発生しない）。

**もう一つ手がある。カメラを寄せる。** 同じ「飛び出した状態」が描かれたコマでも、
**ページ全体から下段のコマへ寄っていく1本のカメラ移動**にすると1回で成立した
（2026-08-28 / 自社検証・H3で1回。実例は `platforms/model-quirks.md`）。

**モデルの挙動は変わっていない。発生そのものは今も描けない。** 変わったのは、被写体を
大きくするしかなかったスケール変化に、**カメラの接近という理由が与えられた**こと。
失敗したときの「巨大化」と成立したときに起きていることは同じで、**動機づけの有無だけが違う。**

選択肢は3つ。**発生前の絵を別に用意する／カメラの接近で代替する／発生の描写を諦める。**

これは `principles/shot-structure.md` の「開始フレームを固定すると、カメラはそのフレームから
動くことしかできない」の時間軸版。**あちらはカメラの自由度、こちらは時間の自由度。**

### 素材固有の記号を動かす

素材が持つ記号を、保持するだけでなく動かす。枠をマスクやトランジションに、
線を粒子に、書き文字を物理を持つタイポグラフィに
（2026-08 / 推測。未検証。語彙は templates/vocabulary.md）。

## 文字を外すかは、動かす量による

**素材に文字が焼き込まれていても、動かす量が小さければ破綻しない。**
H3で漫画コマを動かした範囲では、吹き出しと擬音を残したままでも成立した（自社検証）。

当初は「読める文字を生成中ずっと保持させない」と無条件で書いていたが、
**外部の実務記事に基づく未検証の記述だった。** 自社検証で条件付きに修正した。

### 先に、素材に文字なし版が隠れていないか調べる

**校了PDFでは、絵柄が1bitラスタ、写植セリフが生きたテキストとして別に置かれていることがある**
（InDesign出力の漫画単行本で確認）。この場合 `pdfimages` で取り出すと絵柄だけが得られ、
**吹き出しの輪郭は残って中身が空**——つまり clean plate がそのまま出てくる。
レタッチで作る工程が丸ごと消える。

- **文字入りが要るときはページ全体をレンダリングする。** 両者を画素一致で揃えるには、
  PyMuPDF の `page.get_image_rects(xref)` でラスタ画像の配置矩形をPDF座標で取得し、
  同じ解像度でレンダリングした結果を同じ矩形で切る
- **手描き風の文字と擬音はラスタ側に含まれる。** つまり部分的に文字が残るので、
  **セリフが欠けていることに気づきにくい。** 照合してから使う

（2026-08 / 自社検証。1冊の校了PDF（152頁）。`pdfimages -list` で全77PDF頁を走査し、
17頁で両版を作って寸法と位置の一致を確認。**1冊のみ。** 全ての漫画PDFがこの構造とは限らない）

**この抜け道があるかどうかで、下の判断が変わる。** 「まず文字ありで試すのが最小コスト」は
維持されるが、**文字なし版の費用がゼロなら先に両方作っておく**ほうが早い。

### clean plate 化を検討する条件

**次のいずれかが起きたときだけ。**

- **動かしたい部位を文字が隠している**（顔・口・手など）
- カメラを大きく動かすカットで、文字が固定物として画と競合する
- 文字を別レイヤーで演出したい、後から差し替えたい
- 多言語展開や、他モデルへの移植を想定する

**全コマを前処理しない。破綻したコマだけ後から作る。**
まず文字ありで試すのが最小コスト。

### clean plate は原作から遠ざかる操作でもある

**原稿の文字がそのまま出る状態が、原作にいちばん近い。**
文字を外して作り直すと、上の「原作からの距離を3段階で決める」で1段遠くなる。

原稿を素材にする案件では、**自由度と原作忠実度がトレードオフになる。**
クライアントへの説明も、文字を残すほうが「原稿のままです」で通る。

### 外すときの実体は「消す」ではなく「埋める」

吹き出しの下には元の絵が存在しない。**消した跡を埋める作業になる。**

ただし文字を後工程で同じ位置に戻すなら、**戻したときに隠れる範囲は雑でよい。**
辻褄が要るのは吹き出し輪郭の外側だけ。

**生成での塗りつぶしに頼らない。** 網点と手描き線を再現できずグレーの塗りになる
（→ platforms/model-quirks.md）。**レタッチを頑張るより、文字が絵に食い込んでいない
コマを選び直すほうが速い。**

### 戻し方

- 音声＋字幕
- アニメーションする文字要素
- ショット間のインタータイトル

これは `principles/typography.md` の「コピーとタイポグラフィは固定アセット、
AIは背景・光・粒子・モーションだけ」と同じ責任分配。

## 素材に焼き込まれた文字は、読字予算になる

**文字が絵に焼き込まれている素材では、カットの選定と同時に文字量の設計が発生する。**
絵だけを見て選ぶと、読めない尺に文字が乗る。

20カット構成の各カットで画面文字数を数えたところ、割当秒数に対して**2倍から10倍の超過**が
起きていた。**最長のカットは61字に1.5秒の割当。** 数えた結果、12カットへ削減した
（2026-08 / 自社検証・1案件）。

- **素材を選ぶ段階で1カットずつ文字数を数え、合計を先に出す**
- 複数の吹き出しがあるコマは、**主たる1つだけが入るようにクロップし直せる**
- **図解と文字リストの両方が原稿にあるなら、図解を採る。** 4つの概念を紹介するカットで、
  説明文が主のページから**見出し4語＋絵**のページへ差し替えたところ、画面文字が大幅に減り、
  新規のグラフィックを作る必要もなくなった（2026-08 / 自社検証・1案件）
- **通過するコマの文字は予算に入らない。** カメラがコマの上を通過していく場合、
  読ませているのは**着地点だけ**。説明の吹き出しが多いページでも、着地点を絞れば使える
  （2026-08-28 / 自社検証。ただし**視聴者が実際に読んでいないことの検証ではなく、
  画面上で読める時間が与えられていないことの確認**）

### 変換に使った秒あたりの数値は、出所が無い

作業では**「画面の日本語は毎秒4文字」**を目安に使い、文字数から必要秒数を逆算した。
**この数字の出所を明示できない。** 一般的な目安として流通している値だが、誰がどんな条件で
測ったのかを確認していない。**字の大きさ・読み手の年齢・縦書きか横書きか・動画かどうかで
変わるはずの値を、条件なしで使っている。**

同じく「声を乗せると読字予算が緩む」の根拠——**日本語の早口はおよそ毎秒9〜10モーラ**とされ
読字より速い——も一次資料を確認していない。**なお緩むだけで消えはしない。**
音を切って見る視聴者がいるため、最低限の可読性は残す。

**文字数の実測（61字／20カット分を計数／12カットへ削減）は自社検証。出所不明なのは
秒あたりの変換値だけ。** `DIFF-FORMAT.md` の「数字には誰が測ったかを書く。付いていなければ
落とす」に照らすと本来は落とす数字だが、**落とすとこの節の運用ができなくなるため、
出所不明と明記したうえで残している。** → 末尾「検証したいこと」

## 網点素材の縮小

**素材全体に一律のディスクリーン（網点潰し）をかけない。寄りがあるカットでは損になる。**

600dpi・1bit・網点60線（1セル10.06px）で網点を平坦なグレーに潰すには **σ3.4 相当のガウス**が
要る。この強さは、**等倍で見せる寄り端**——縮小が起きずモアレも発生しない領域——で
線画を明確に劣化させる。

一方、**縮小を面積平均（BOX / `INTER_AREA`）で行えば、無処理のままでも網点は平坦なグレーに
落ちる。** 崩れるのはバイリニアとニアレストで、その場合は **σ1.2 程度の弱いプリブラー**で
ほぼ回復する。

**したがって、ディスクリーンはリサンプラーを制御できない工程にだけ弱くかける。**
NLE側のズーム・パンがそれにあたる。自前で縮小する工程はアルゴリズムを選べるので不要。

σ の目安は**セル幅 × 0.35 前後**（10.06 × 0.34 ≒ 3.4）。セル幅は `dpi ÷ 線数`。

0.347倍と1.00倍で目視比較。あわせて縮小アルゴリズム4種（面積平均／バイリニア／ニアレスト／

## 止まりを残す

**全ショットを常時動かさない。** 静止・微動・完全な動きを使い分け、
重要な台詞や反応の前後に止まりを残す。

漫画や書籍は読者がタイミングを制御する媒体で、映像化すると制御が制作側へ移る。
**その差を止まりで埋める**（2026-08 / 外部の実務記事。自社未検証）。

これは編集の5つの破綻のうち「ペース」にあたる。唯一の個別判断なので型にはしにくいが、
**素材由来のカットでは止まりが既定値**と考えてよい（→ principles/workflow.md）。

## 冒頭を静止から始める場合

冒頭を完全に静止した素材として見せ、遅れて瞬き・視線・発話・枠の突破を発生させる構成。
**静止した媒体だと思ったものが生命を持つ**、という認知の差をフックにする
（2026-08 / 推測。視聴データなし）。

**これは自社の失敗例と構造が同じ。** 成立条件3つを満たすこと
（→ principles/workflow.md の「静止から始めてよい場合」）。

## 参照の扱い

素材、キャラクターシート、場所、モーション参照、音声参照を同時に使うときは、
**各参照から何を継承するかを明記する**（→ principles/shot-structure.md）。
素材の画風と動きが混線するのを防ぐ。

素材を渡す場合、その素材が支配するのは通常「構図・画風・被写体の見た目」で、
**動きは支配しない**。ここを書き分けないと、動かしたいのに動かない、あるいは
画風が流れる、のどちらかになる。

## 分からないこと

- 線画を保持したまま2枚の間を補間する性能。定量評価した資料は確認できていない
  （H3で1案件3回だけ観測した。線と網点は保たれ、モーフィングにも逃げなかった。
  **定量ではないのでこの項目は埋まっていない**）
- 1枚から別アングルを生成する機能について、絵柄ごとの成功率・線の保持率・
  複雑な網点の保持率
- 文字を生成内で保持する場合の可読率。モデル横断の比較資料は確認できていない
- 「静止 → 微動 → 完全な動き」の段階的起動が視聴維持率を上げるというデータ

## 検証したいこと

1. 同一素材で「完全静止」「瞬きだけ」「髪＋環境だけ」「全身の芝居」の4条件を作り、
   原画の保持と違和感を比較
2. 同じ2枚を始点・終点として与え、中間動作の破綻・線の保持・同一性・背景の整合を確認
3. 素材を別アングル生成へ入れ、立体化せずに別アングルが出るかを絵柄別に確認
4. **画面文字の読字速度。** 字幕の可読性についての一次資料（放送の字幕規格、SNS動画の
   読了率を測った資料）を当たる。**現在使っている「毎秒4文字」「毎秒9〜10モーラ」は出所不明**
4. 同じ素材へ、文章だけの動作指定とモーション参照を与え、ポーズ・画風・顔の保持を比較
5. 文字入り素材をそのまま渡す条件と、文字なし clean plate → 後載せ条件を比較
6. **素材のまま → 微動 → 枠の突破 → 完全な動き → 素材へ戻る を各段階で別生成し、
   どの境界で原作感が失われるかを記録する**
7. 「完全静止から突然動く」冒頭と、最初から常時動く冒頭を比較（維持率が取れる案件で）

**6番の優先度が高い。** 原作感が失われる境界が分かれば、クライアントに
「ここまでは動かせます」と根拠付きで言える。承認設計の「スタイルフレームの承認」段階で
そのまま使える材料になる（→ OPERATIONS.md）。
